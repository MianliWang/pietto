# Pietto Diagnostic Codes

Pietto diagnostics use the canonical format:

```text
PIE-<PHASE><NUMBER>
```

`PHASE` identifies the compiler or execution stage:

| Prefix | Stage |
|---|---|
| `PIE-P` | Parser, lexer, and indentation |
| `PIE-S` | Semantic analysis |
| `PIE-I` | IR and SQL compilation |
| `PIE-B` | Backend capabilities |
| `PIE-R` | Runtime and execution |

`NUMBER` is a four-digit identifier within the phase. Diagnostic severity is
stored separately and is never encoded in the code.

## Parser Diagnostics

| `PIE-P1000` | Syntax or AST-construction error. Parser recovery reports at most one error per top-level declaration, without repeating a declaration's indentation, brace or unterminated-string cause. Token text is escaped deterministically (`\t`, `\n`, `\r`, `\xNN` or `\uNNNN` for controls as appropriate); expected categories include `an expression` and `a name`. Separately, modern spelling admission runs before AST normalization and reports every retired-spelling occurrence in source order. Its message is `This spelling is not accepted by the modern syntax.` followed by the precise rewrite, such as `Write 'is None'.`, which the JSON `suggestion` field also carries, so text output states the fix on the diagnostic's one line. ## Semantic Diagnostics

Source examples use `None`, `True`, `False`, `having` and `let name = value`.
A fix that a message or suggestion states is written in current spelling,
such as `is None`, `| None`, `having` or `let name = expression`. A message may
still describe a value with an internal term such as `null`; that text does not
re-enable retired source spelling.

`PIE-S2104` also covers malformed calls of the closed scalar forms and of
`string_agg`: unshadowed `Float` and `Text` each use a one-Int constructor
boundary; `round` accepts only Decimal with an optional static scale in
`-30..30` or one Float argument; `date_trunc` needs a static admitted unit and
Date/Timestamp input; `string_agg` needs two Text
arguments and a nonempty internal ORDER BY: a `None` argument, also through a
`let` name or built only of `None` values (`coalesce(None, None)`, `-None`, or
a conditional such as `None if id > 1 else None`, whose condition is no value
of it), is `expected two Text arguments`. `string_agg` as a window is refused.
A project check reports a `string_agg` without its internal ORDER BY with the
single-file message (`Invalid arguments for aggregate string_agg: expected
ORDER BY key`) at the call, and, with or without JOIN inputs, its other
malformed aggregate calls with their single-file codes and messages at the
call. Without JOIN inputs a project reports the aggregate, grouping, grouped
ORDER BY and `having` errors of PIE-S2104, PIE-S2310 to PIE-S2315,
PIE-S2318 to PIE-S2321 and PIE-S2323 to PIE-S2327, and in `having` also
PIE-S2105, PIE-S2202 and PIE-S2308, as a single file does, over a row whose
fields are known (a grouped ORDER BY key that names a selected window result
is checked with the window); so are an unknown field (PIE-S2102) in an
aggregate projection or a GROUP BY key, an aggregate's argument count
(PIE-S2309) and an invalid LIMIT (PIE-S2307), also beside the other errors;
an aggregate argument whose type a field declares through an alias is named
by that alias (`got Whatever`). A relation over a row of unknown type,
or one that reads a relation, a captured field, a query parameter or
`any(...)` in its SELECT items or ORDER BY, is still the bare PIE-S2333 at the
relation, and so is one whose shape-typed field an aggregate reads; one that
reads a nested relation field there reports PIE-S2805 for that read instead
of these checks. A relation that already reports an error of its own gets no
bare PIE-S2333 beside it.

Residual: a project also reports the bare PIE-S2333 at some relations that a
single file accepts or refuses with another code, for example one whose
SELECT output is an always-null number such as `o0 = None - 3.0`. As for any
failed relation (see PIE-S2333), the relations that read it report none of
their own errors, such as an invalid LIMIT or an unknown field, until it is
fixed. These project-only cases also remain:

- A source whose imported shape fails in another module for an error inside
  its declaration other than an unknown type, such as a duplicate field
  (PIE-S2501), adds the bare PIE-S2333 at the source beside that error; with
  the shape in the source's module, only that error is reported.
- A source whose shape has a field type that is an alias, declared in
  another module, of a name that module imports with a relation kind
  (`from "w.pietto" import (source M)` for a type M, PIE-S2705) adds the bare
  PIE-S2333 at the source beside that PIE-S2705.
- A source without a shape in a module that reports another error gets no
  PIE-S2333, and so no `(source items has no shape, ...)` cause, until that
  error is fixed.
- A module that declares a source or shape twice and exports it reports
  PIE-S2704 `Ambiguous local export declaration: source s` at the export,
  where a single file, or the module without that export, reports PIE-S2001
  at the second declaration.

Each fails closed with an error reported; naming the cause at each such
relation, and the single-file code, is deferred.

A LEGACY_FLAT project check (schema version 1) analyzes its selected files as
one single file in selected order once they parse and pass its pre-admission
checks, so the historical non-JOIN scalar rules described below generally also apply.
Modern single-file JOIN and ANY support does not by itself admit those forms
in LEGACY_FLAT. The other exceptions are as follows. It emits no SQL, so it types a field of an alias of an
enum as that enum, as an EXPLICIT_MODULES check does, and makes none of the
refusals that only single-file SQL needs: PIE-S2328, the PIE-S2104 ROWS and
GROUPS window frame offset and window count literal ranges, the bare-constant
ORDER BY key of PIE-S2380, the PIE-S2329 conflict of a `let` name with an
unaliased SELECT item that names it in a relation with GROUP BY, the PIE-S2315 of a `min` or `max` whose
argument is a `let` name in a relation without GROUP BY, and the PIE-S2306
that only single-file checks report for a source connector, so a connector
gets the diagnostics of
an EXPLICIT_MODULES check. It does not type JOIN binding fields or use the
single-file JOIN resolution, nullability, cycle and fan-out rules introduced
here; it checks no JOIN and no `any(...)` of the current syntax, each of which
is one PIE-S2334 (see PIE-S2334). It also does not type
computed `let` group keys or aggregates of `let` names in a relation with
GROUP BY, which EXPLICIT_MODULES checks type, so it reports nothing
inside a table or query that reads a field of one of its JOIN bindings or
reads a `let` name in a GROUP BY key or in an aggregate of a relation with
GROUP BY, or that reads such a relation with `from` or a JOIN, directly or
through others. Analysis that reaches the single-file bound (PIE-S2006), such
as an expression nested past it in any of its files, leaves only the
diagnostics of its legacy-flat project model, without PIE-S2006. It reports
these diagnostics after those of its legacy-flat project model, without
repeating one that the model reports, and omits the diagnostics that a check
mode selects (PIE-S2303 for a source without a shape, and PIE-S2304), as
project commands take no check mode.

Every plan-stage refusal (`order`, `group`, `join`, `window`, `qualify`, ...) is located at its clause where it has one, else at the declaration. An aggregate over an argument outside its reviewed domain is `<function>_argument_outside_reviewed_int_domain` for `count`, `count_distinct`, `min` and `max`: each admits an Int argument, `count` and `count_distinct` also an exact Timestamp, Date or UUID argument, and on PostgreSQL `min` and `max` also an exact Timestamp or Date argument, and every other type is refused (only `sum` and `avg` of a Decimal or Float argument are PIE-B1004 range or finite-result proofs); each refused aggregate is reported at its own select item, in select order, and a refused group key at its GROUP BY item. In text output, a blocker an author can resolve (a missing or mismatched premise, an unreviewed release, `order`, an Int arithmetic range) is followed by a `hint:` line naming the reviewed value or remedy |
| `PIE-B1004` | MISSING_EVIDENCE: required existing logical meaning, validated Decimal parameters or environmental declaration is absent. Includes `sum_int_aggregate_range_proof_missing`: a MySQL `sum` of an `Int` argument (PostgreSQL emits it as `CAST(SUM(CAST(x AS pg_catalog.int8)) AS pg_catalog.int8)`, which may fail while PostgreSQL plans or executes the statement with SQLSTATE 22003 and never returns a wrong value), and the range or finite-result proofs of a `Decimal` or `Float` `sum` or `avg` |
| `PIE-B1005` | PREMISE_CONFLICT: the selected rules cannot use the supplied declarations coherently |
| `PIE-B1006` | UNFULFILLED_REQUIREMENT: applicable original negative/conflicting target evidence or mandatory enforcement remains unresolved |
| `PIE-B1007` | TARGET_RESOURCE: emitted structure, SQL bytes or public artifact exceeds a compiler or stricter declared target limit. A generated SELECT counts the physical columns it writes: a Collect column is its count and one array per child, and a collected let's terminal adds its ordinal. A row or JOIN plan whose stages carry more columns than half the generated-node limit (32768, or a stricter declared `nodes`), as a long `let` chain does, each stage carrying every earlier column, is refused with `generated_structure_limit` once its contract is read, before it is assessed or realized, beside no other blocker than a premise conflict (PIE-B1005) |
| `PIE-B1008` | ARTIFACT_INTEGRITY: actual SQL AST, final bytes, ranges, parameters, requirements or current input roots fail correspondence |

These additional codes are implemented by the private Phase66 Slice3 emission
pipeline and its `pietto.sql-emission.v1` serialization (`pietto.sql-emission.v2`
for a VERIFIED query with header parameters). They do not expand the
single-file emitter's `PIE-B1000` domain or implement later operator families.
Single-file JOIN refusals stay PIE-B1000; the project pipeline keeps its own
FULL JOIN domain and reports unsupported target rules with PIE-B1003.

## Runtime Diagnostics

These codes belong to the public execution alpha (`pietto.execution`, see
[Execution](../execution.md)). They are an alpha interface: a code may be split,
merged or retired with a note in the release notes, but is never reused for
another meaning. They appear only on that Python interface, never in a CLI or
JSON output. Each error also carries an unstable private `detail` word. Every
attempt outcome carries the alpha's two declarations:

- `Managed operator compliance: NOT_INDEPENDENTLY_VERIFIED`
- `Native all-definition lifetime exclusion: NOT_DEMONSTRATED / NOT CLAIMED`
